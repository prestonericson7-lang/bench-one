# psram_llm — a 3-billion-parameter language model on a Teensy 4.1

Qwen2.5-Coder-3B (Q4_K_M, **3,085,938,688 parameters**, 1,929,903,072-byte GGUF) on a Teensy 4.1 whose own RAM
is 1 MB. **The whole model stays on the built-in microSD**: every weight, norm and bias is read from
`qwen3b.gguf` every token, and the tokenizer's lookup tables are in `qwen3b.tok` beside it (built by the board
from the model the first time, checked every boot). **The PSRAM is the model's working memory only**: the
attention cache, 3,072 positions. The Teensy's own RAM does the arithmetic. Usable numbers: `docs/55`; the
story and every measurement: `docs/54`.

## Commands (USB serial, one line each)

| send | effect |
|---|---|
| a prompt | runs it; `\n` `\t` `\\` are unescaped so code and chat templates fit one line |
| `I` | `I bench-one psram_llm v8 banks N ps_bytes N max_seq N gen N sdio dma overlap 1 align 1 slice 0` |
| `::gen N` | tokens to generate, 1–512 (default 16) |
| `::prefill 0\|1` | prompt through `tl_prefill` (default 1) or one token per pass |
| `::multi K` | the next K prompt lines (1–8) are answered together, one pass over the weights for all of them; lines `S<k> step …`, `ANSWER S<k>: …`, one `RUN multi=…`. `::multi 0` cancels |
| `::share 0\|1` | in a `::multi`, a prompt opening with the same tokens as an earlier one copies those cache rows instead of computing them (default 1); `RUN` gains `shared=N` |
| `::sdio fifo\|dma` | restart the card in FIFO_SDIO (v6's way) or DMA_SDIO (v7's default) |
| `::overlap 0\|1` | DMA only: work the rows of the block already read while the next block comes off the card (default 1) |
| `::align 0\|1` | DMA only: read the whole sectors around a block, one card command instead of two or three (default 1) |
| `::slice N` | rows per `yield()` during a DMA wait: 0 = one row (default), N = N µs of rows. These four move only the time; the step lines must not change |
| `::sdclksweep` | the card clock above SdFat's 49.5 MHz (66, 99 MHz): 8 MB in four places read twice at each and checked byte for byte; keeps the fastest by measured rate (`CLKSWEEP …` lines). **Runs at every boot** |
| `::sdclk N` | card clock = 198 MHz / N (2–16); `::sdclk 0` = SdFat's 49.5 MHz. A failed read above 49.5 MHz drops back for good and retries |
| `::sdsweep` | the DMA path's read watermark × burst length × burst enables, each 2 MB checked against FIFO; keeps the fastest that reads right (`SWEEP …` lines) |
| `::sdcfg W B L`, `::sdregs` | set the DMA watermark/burst by hand (`::sdcfg 0` = SdFat's); dump the SD controller's registers |
| `::bench` | card at 4/16/64 KB and random 4 KB; the M7 kernels on real Q4_K and Q6_K rows, and the Q4_K dot timed in stages (`BENCH q4k_stage`); v6 adds the batched kernel with 8 vectors (`BENCH kernel_x8`); PSRAM raw and self-checked on a free bank |
| `::stats` | banks, settings, PSRAM self-check counters, temperature |
| `::hold` | nothing; a host sends it in the 30 s boot window so the default prompt does not run |
| `::stop` | stops a run at the next card-read boundary. **Send before any flash** (bench_run.py does) |

Machine-readable lines: `step …` (same format as the PC proof), `STAGES …`, `RUN …`, `BENCH …`, `STATS …`.
v7: `STAGES` ends with `hidden=` and `RUN` has `hidden_s=` — arithmetic done while the card was reading. `sd_s`
then counts only the card wait left over, so `sd_mbs` is bytes over that wait, not the card's own rate.

## Proven on the PC first

```bash
cd firmware/bench-one/tests
gcc -O3 -fopenmp -std=c11 -Wall -Wextra -I../shared -o tl_ref.exe tl_ref.c ../shared/model_q.c ../shared/gguf.c ../shared/gguf_bits.c ../shared/gguf_dot.c ../shared/tokenizer.c -lm
gcc -O3 -fopenmp -std=c11 -Wall -Wextra -I../shared -o tl_host.exe tl_host.c ../shared/tl_core.c ../shared/gguf_dot.c ../shared/gguf_bits.c -lm
./tl_ref.exe  MODEL.gguf "The capital of France is" 16 > ref.txt
./tl_host.exe MODEL.gguf "The capital of France is" 16 > host.txt
TL_PREFILL=1 ./tl_host.exe MODEL.gguf "The capital of France is" 16 > prefill.txt
diff ref.txt host.txt && diff ref.txt prefill.txt
```

Identical, token ids and logits to nine digits, on the France prompt, a code/UTF-8/control-token prompt, a
123-token prompt, the suite's prompts, and a 16 MB PSRAM layout. PC numbers are correctness only.

All of it in one run, with a report in `bench-archive/<stamp>-psram_llm-pcverify/`:

```bash
python firmware/bench-one/tests/psram_llm/verify_pc.py
```

The Teensy's own kernels (the M7 `SXTB16`/`SMLAD` code) run on the PC through a C emulation of those
instructions; both commands must print only IDENTICAL:

```bash
cd firmware/bench-one/tests
gcc -O2 -std=c11 -Wall -Wextra -DGD_EMULATE_M7 -I../shared -o dot_verify_m7.exe dot_verify.c ../shared/gguf_dot.c ../shared/gguf_bits.c -lm
./dot_verify_m7.exe 1024 11008
gcc -O2 -std=c11 -Wall -Wextra -DGD_EMULATE_M7 -I../shared -o tl_host_m7.exe tl_host.c ../shared/tl_core.c ../shared/gguf_dot.c ../shared/gguf_bits.c -lm
```

`tl_host_m7.exe` is the whole Teensy forward pass, M7 kernels included, and diffs against `tl_ref.exe` like
`tl_host.exe` does (slowly: every kernel instruction is emulated).

For the llama.cpp tokenizer comparison start its server first (it ships with Ollama):
`"%LOCALAPPDATA%/Programs/Ollama/lib/ollama/llama-server.exe" -m MODEL.gguf --host 127.0.0.1 --port 8089 -c 512 -t 2`.

## Test process

1. Card with `qwen3b.gguf` in the Teensy's slot, Teensy on USB.
2. `python firmware/bench-one/tests/psram_llm/suite.py --flash` — builds, archives and flashes through
   `tools/bench_run.py` (asks `::stop`, then `I`, refuses a board that ever answered as something else),
   holds the boot window, then runs every test in `tests_night2.txt` **three times, in rounds** (run 1 of
   every test, then run 2, then run 3), with one `::bench` at the start of each round.
   `--wait-power-cycle` instead waits for the Teensy to be unplugged and plugged back in, then runs.
3. Each run is checked twice: against `tests/tl_ref.exe` on the same prompt (token ids exactly, logits
   numerically, first divergence and the reference's own margin there) and against that test's first run
   on the board (must be identical — the board against itself is deterministic or something is wrong).
4. `bench-archive/<stamp>-psram_llm-suite/`: `serial.log` (every line, host-timestamped), `<test>.expected.txt`,
   `results.jsonl`, `summary.md` rewritten after every run.

Test files: `id | tokens to generate | prompt`, one per line; `#` comments; lines starting `::` are sent to the
board as commands (e.g. `::prefill 0` before an A/B test); `@multi <id> | <tokens>` … `@end` around
`id | prompt` lines is a group answered together. `summary.md` also checks that tests reaching the same prompt
by different paths (batched, per token, inside a group) printed identical step lines.

## If the card will not start

`SD begin attempt N failed: SdFat error 0x17` (ACMD41) on every attempt = the card is hung, usually by a reboot
while it was being read. Unplug the Teensy's USB for 2 s. A reset or reflash does not clear it.
